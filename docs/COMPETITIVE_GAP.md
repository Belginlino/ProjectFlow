# Competitive Gap

## Existing systems already handle
- projects
- tasks
- milestones
- workflows
- dependencies
- reports
- collaboration
- automation

These should not be claimed as unique.

## Gaps ProjectFlow targets
1. Task completion does not necessarily prove evidence or learning.
2. Task ownership does not fully prove individual contribution.
3. Code, tests, documents and reviews can remain disconnected.
4. Feedback can remain disconnected from revision and verification.
5. Progress percentages do not explain root causes.
6. Final evaluation can be disconnected from day-to-day evidence.
7. Generic project systems are not centered on learning outcomes.
8. Decision history can be fragmented across tools.

## Positioning
> Existing platforms are strong at managing project work. ProjectFlow makes evidence, contribution, feedback, learning and evaluation relationships first-class.

Do not claim that competitors cannot technically implement these features.
