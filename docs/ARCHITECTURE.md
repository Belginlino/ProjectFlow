# ProjectFlow Architecture

## Architecture Decision

ProjectFlow uses a Firebase-first serverless architecture for rapid development, real-time collaboration, and simple deployment.

### Stack
- Frontend: React + Vite + TypeScript
- Authentication: Firebase Authentication
- Primary database: Cloud Firestore
- Evidence/file storage: Firebase Storage
- Backend/serverless logic: Firebase Cloud Functions
- Hosting: Firebase Hosting (or equivalent static hosting)
- Integrations: GitHub API and approved external APIs
- AI: evidence-grounded AI invoked through Cloud Functions
- Security: Firestore Security Rules, Storage Rules, and App Check where appropriate

## Flow
React UI → Firebase Auth → Firestore / Storage → Cloud Functions → GitHub / AI / notifications

## Evidence Graph
Requirement → Task → Work → Evidence → Review → Feedback → Change Request → Revision → Verification → Contribution → Evaluation → Learning Outcome

Firebase is the implementation platform; the Evidence Graph is the product innovation.

## Firestore Structure
```text
projects/{projectId}
  requirements/{requirementId}
  tasks/{taskId}
  evidence/{evidenceId}
  evidenceLinks/{linkId}
  reviews/{reviewId}
  changeRequests/{changeRequestId}
  reflections/{reflectionId}
  evaluations/{evaluationId}
  viva/{vivaId}
  healthAlerts/{alertId}

users/{uid}
institutions/{institutionId}
rubrics/{rubricId}
skills/{skillId}
learningOutcomes/{outcomeId}
auditLogs/{logId}
```

Use `evidenceLinks` when an evidence item needs relationships to multiple entity types. Store files in Firebase Storage and metadata in Firestore.

## Cloud Functions
Use Functions for trusted mutations, GitHub synchronization, contribution aggregation, project-health calculation, notifications, AI orchestration, and sensitive audit operations.

## Security
Rules must enforce authentication, project/team membership, roles, institution boundaries, safe file access, and restricted evaluation/audit operations. Never expose Firebase Admin credentials to the client.

## Query Strategy
Design Firestore queries before implementing screens. Add only required composite indexes. For complex analytics, use derived/materialized summary documents generated by trusted Functions while preserving source evidence and auditability.

## Environments
Prefer separate Firebase projects for development, staging, and production. Keep secrets out of source control.
